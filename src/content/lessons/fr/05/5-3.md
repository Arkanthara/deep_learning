## Comprendre le problème

Un optimiseur reçoit les paramètres qu’il doit modifier et conserve éventuellement un état, par exemple le momentum. Une boucle standard efface les anciens gradients, calcule les prédictions et la perte, appelle backward, puis step. C’est step qui modifie les paramètres.

## Le mécanisme

Passer de SGD à Adam change la règle et l’état d’optimisation, pas la définition de forward. Les groupes de paramètres permettent des réglages distincts. Un oubli de paramètres ou une remise à zéro après backward peut empêcher l’apprentissage. Vérifier une petite boucle sur un petit lot facilite le diagnostic.

$$
\mathrm{zero\_grad}\ \to\ \mathrm{forward}\ \to\ \mathrm{backward}\ \to\ \mathrm{step}
$$

## Approfondir le raisonnement

Un optimiseur conserve des références aux objets Parameter, pas une recette pour retrouver automatiquement tous les futurs poids. Si l’on remplace une couche, il faut mettre à jour ses groupes ou recréer l’optimiseur. Sa vitesse d’apprentissage et son état doivent être sauvegardés pour une reprise cohérente. Pour déboguer, vérifier d’abord que la perte dépend bien des paramètres, que les gradients ne sont pas tous absents et que step change une valeur. Une boucle capable de surajuster un tout petit lot est un contrôle utile de fonctionnement.

## Exemple pas à pas

optimizer.zero_grad(); loss = criterion(model(x), y); loss.backward(); optimizer.step() décrit une mise à jour. L’appel model.train() règle les couches sensibles au mode, comme dropout et batch normalization.

## Lire le code

Exemple à exécuter dans un environnement Python avec PyTorch. L’exécution dans le navigateur est prévue pour la V2.

```python
import torch
from torch import nn

torch.manual_seed(7)
x = torch.randn(32, 4)
y = (x[:, 0] > 0).long()
model = nn.Linear(4, 2)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
criterion = nn.CrossEntropyLoss()
model.train()
for step in range(20):
    optimizer.zero_grad(set_to_none=True)
    loss = criterion(model(x), y)
    loss.backward()
    optimizer.step()
print(loss.item())
```

## Exercice de compréhension

loss.backward() donne des gradients non nuls mais les poids ne changent pas. Cite deux causes possibles.
