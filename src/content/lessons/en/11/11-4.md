## Understand the problem

Saving a model allows its parameters to be reused without retraining. A state_dict contains registered parameters and buffers. It is generally more flexible than serialising the entire Python object, which depends heavily on the code and class used when saving.

## How it works

To resume training, also save optimiser state and the step or epoch. Faithful continuation may require scheduler, random-generator and gradient-scaler states. Recreate the architecture, load weights, then restore required states. map_location handles loading on different hardware; eval configures inference behaviour but does not itself disable autograd.

$$
\mathrm{checkpoint}=\{\theta,\ \mathrm{optimizer\ state},\ \mathrm{step},\ldots\}
$$

## Develop the reasoning

A reproducible checkpoint should also record configuration: dimensions, data version, normalisation and class definitions. Exact trajectory continuation also depends on batch order and random states. For inference, weights and buffers suffice when architecture and preprocessing are correctly reconstructed. Loading onto CPU before moving the model can ease portability. Serialised files should come from a trusted source; the example explicitly uses `weights_only=True` and state dictionaries rather than arbitrarily serialising an entire Python class.

## Worked example

Adam maintains averages of gradients and squared gradients. Loading only weights and creating a fresh Adam can change subsequent updates, even with the same next mini-batch.

## Read the code

Run this example in a Python environment with PyTorch. In-browser execution is planned for V2.

```python
import torch
from torch import nn

model = nn.Linear(4, 2)
optimizer = torch.optim.Adam(model.parameters())
torch.save({
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
    "epoch": 0,
}, "checkpoint.pt")
checkpoint = torch.load("checkpoint.pt", map_location="cpu", weights_only=True)
model.load_state_dict(checkpoint["model"])
optimizer.load_state_dict(checkpoint["optimizer"])
model.eval()
```

## Understanding check

Why might a loaded model still produce stochastic outputs even with correct weights?

<details>
<summary>Reveal the worked answer</summary>

It may remain in train mode with active dropout. Calling eval controls that behaviour; no_grad or inference_mode separately avoids gradient tracking.

</details>
