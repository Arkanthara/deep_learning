## Understand the problem

A convolution applies the same local filter at multiple positions. Weight sharing reduces parameter count and exploits spatial structure. In vision, each filter combines all input channels to produce one output channel; multiple filters produce a multichannel map.

## How it works

Padding adds a border, stride spaces evaluated positions and dilation spaces filter coefficients. The receptive field describes the input region influencing an output. Convolution is associated with translation equivariance, with boundary and subsampling caveats; it does not automatically provide invariance.

$$
H_{out}=\left\lfloor\frac{H+2p-d(k-1)-1}{s}+1\right\rfloor
$$

## Develop the reasoning

Effective filter size is $k_{eff}=d(k-1)+1$. After padding there are H+2p positions. The final valid start cannot exceed H+2p−k_eff; counting starts spaced by s explains the floor in the output formula. For standard convolution with groups=1, weight count is C_out×C_in×k_H×k_W, plus C_out biases. This does not depend on image resolution, unlike computation cost, which grows with output positions.

## Worked example

With H = 32, kernel 3, padding 1, stride 2 and dilation 1, output height is 16. A 3 → 16 channel layer has 16×(3×3×3+1) = 448 parameters including bias.

## Understanding check

A bias-free 8→16 convolution with 3×3 kernels processes an image doubled in height and width. Does its parameter count change?

<details>
<summary>Reveal the worked answer</summary>

No: it stays 16×8×9=1,152. However, with comparable spatial settings, position count and computation grow approximately fourfold.

</details>
