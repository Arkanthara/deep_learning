## Understand the problem

A module packages a computation and, optionally, its parameters. A linear layer transforms a tensor’s last dimension. Grouping examples into mini-batches expresses computation as efficient matrix operations instead of a Python loop over examples.

## How it works

With examples as rows, X has shape B × D and the weight of nn.Linear(D,M) has shape M × D. Computation therefore uses XWᵀ and broadcasts the bias over B rows. The loss may sum or average across the batch; this changes gradient scale.

$$
Y=XW^\top+\mathbf1 b^\top,\quad X\in\mathbb R^{B\times D},\ W\in\mathbb R^{M\times D}
$$

## Develop the reasoning

Batch processing vectorises independent computations; it does not by itself change the function applied to each example. Modules such as BatchNorm are an exception during training because they use shared statistics. Batch size B affects memory, update frequency and gradient noise. For mean loss, doubling a batch by repeating exactly the same examples leaves the gradient unchanged; for sum loss it doubles it. This matters when comparing experiments and accumulating gradients over multiple mini-batches.

## Worked example

An input (32,10) passed to Linear(10,4) gives (32,4). All 32 examples use the same 44 parameters: 40 weights and 4 biases.

## Understanding check

A batch contains losses 2 and 6. What are the sum and mean? What happens if the batch is repeated twice?

<details>
<summary>Reveal the worked answer</summary>

The sum is 8 and mean 4. After repetition, the sum is 16 and mean remains 4. Corresponding gradients follow the same scaling.

</details>
