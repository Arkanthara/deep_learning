## Understand the problem

A custom model inherits from nn.Module. Its constructor initialises submodules and its forward method describes computation. Calling the parent constructor enables parameter registration. Using model(x) also triggers hook mechanisms; calling forward directly bypasses them.

## How it works

Submodules assigned as attributes are recursively registered. An ordinary Python list does not provide this guarantee: use ModuleList or Sequential. The optimiser sees registered parameters through model.parameters(). If forward uses autograd-compatible operations, a manual backward pass is unnecessary.

$$
(B,C,H,W)\xrightarrow{\mathrm{Flatten}(1)}(B,CHW)
$$

## Develop the reasoning

Registration establishes a submodule tree. It enumerates parameters, builds checkpoints, moves tensors and propagates train/eval modes. `nn.Parameter` marks an optimisable value; `register_buffer` suits nonoptimised tensor state, such as a constant or persistent statistic. `ModuleList` registers elements without defining computation: the loop remains in forward. `Sequential` additionally defines a pipeline. Creating new layers inside forward would recreate their parameters on every call.

## Worked example

After a convolutional output (B,16,7,7), Flatten(start_dim=1) produces (B,784). The next layer must therefore accept 784 features without flattening the batch.

## Read the code

Run this example in a Python environment with PyTorch. In-browser execution is planned for V2.

```python
import torch
from torch import nn

class Classifier(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Conv2d(1, 16, kernel_size=3, padding=1),
            nn.ReLU(), nn.MaxPool2d(2),
            nn.Flatten(start_dim=1),
            nn.Linear(16 * 14 * 14, 10),
        )

    def forward(self, x):
        return self.layers(x)

print(Classifier()(torch.randn(8, 1, 28, 28)).shape)
# torch.Size([8, 10])
```

## Understanding check

Where should a trainable Linear layer be created: in __init__ or on every forward call?

<details>
<summary>Reveal the worked answer</summary>

In __init__, then use it in forward. The Parameter object must persist across steps so the optimiser preserves learning and, when applicable, its state.

</details>
