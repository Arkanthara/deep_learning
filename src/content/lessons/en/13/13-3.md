## Understand the problem

The Transformer makes attention the central communication mechanism between positions. Each block combines multi-head attention, a positionwise network, residual connections and normalisation. Multiple heads learn different projections and relationships; their outputs are concatenated and projected. Positional encoding complements embeddings.

## How it works

### Encoder and decoder

In the original translation architecture, the encoder sees the entire source. The decoder combines causal self-attention on the known target prefix, cross-attention to the source and a positionwise network. Training can use all shifted targets simultaneously; generation computes new tokens in order. Normalisation can precede sublayers (pre-norm) or follow residual addition (post-norm), affecting optimisation.

### BERT, GPT and in-context learning

BERT uses a bidirectional encoder, notably trained to recover masked tokens. GPT uses a causal decoder architecture for next-token prediction, without requiring cross-attention to a separate encoder. Providing examples in a prompt can steer predictions without updating weights: this differs from fine-tuning.

### Images as sequences

ViT splits an image into patches, projects their pixels into embeddings and applies a Transformer with positional information. Swin uses shifted local windows and a hierarchy to limit cost and structure interactions. DETR combines a visual feature extractor with a Transformer and object queries; training matches predictions to a set of target boxes. These models change inductive bias and cost, not the need for data and rigorous evaluation.

$$
\operatorname{MultiHead}(Q,K,V)=\operatorname{Concat}(H_1,\ldots,H_h)W_O
$$

## Develop the reasoning

Each head has its own Q,K,V projections; the positionwise network then applies the same nonlinear transformation independently to tokens. Attention routes information between positions while this network transforms features within each position. For sequence length T, dense attention forms T² scores per head: doubling T quadruples this part of computation and naive storage. Generation can reuse prefix keys and values instead of recomputing them fully. Vision architectures change token count and allowed interactions to control these costs.

## Worked example

A 224×224 image split into 16×16 patches gives 14×14 = 196 tokens before any class token is added. Dense attention then forms a 196×196 matrix per head. Halving patch size quadruples token count and multiplies the pair count by sixteen.

## Understanding check

A ViT goes from 196 to 784 tokens without changing head count. How does the number of dense attention scores change?

<details>
<summary>Reveal the worked answer</summary>

Token count increases fourfold and pair count by 4²=16. This does not imply total model time increases exactly sixteenfold: other operations have different costs.

</details>
