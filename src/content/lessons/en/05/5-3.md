## Understand the problem

An optimiser receives the parameters it should modify and may maintain state, such as momentum. A standard loop clears old gradients, computes predictions and loss, calls backward, then step. It is step that updates the parameters.

## How it works

Switching from SGD to Adam changes the update rule and optimiser state, not the forward definition. Parameter groups allow different settings. Missing parameters or clearing gradients after backward can prevent learning. Checking a small loop on a small batch simplifies debugging.

$$
\mathrm{zero\_grad}\ \to\ \mathrm{forward}\ \to\ \mathrm{backward}\ \to\ \mathrm{step}
$$

## Develop the reasoning

An optimiser keeps references to Parameter objects, not a recipe to rediscover all future weights. Replacing a layer requires updating parameter groups or recreating the optimiser. Learning-rate settings and state should be saved for consistent continuation. When debugging, first check that loss depends on parameters, gradients are not all missing and step changes a value. A loop able to overfit a tiny batch is a useful functional check.

## Worked example

optimizer.zero_grad(); loss = criterion(model(x), y); loss.backward(); optimizer.step() describes one update. model.train() configures mode-sensitive layers such as dropout and batch normalisation.

## Read the code

Run this example in a Python environment with PyTorch. In-browser execution is planned for V2.

```python
import torch
from torch import nn

torch.manual_seed(7)
x = torch.randn(32, 4)
y = (x[:, 0] > 0).long()
model = nn.Linear(4, 2)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
criterion = nn.CrossEntropyLoss()
model.train()
for step in range(20):
    optimizer.zero_grad(set_to_none=True)
    loss = criterion(model(x), y)
    loss.backward()
    optimizer.step()
print(loss.item())
```

## Understanding check

loss.backward() produces nonzero gradients but weights do not change. Give two possible causes.

step may not be called, the learning rate may be zero, or optimiser parameters may differ from the active model’s. Also check that old weights are not reloaded after the update.
