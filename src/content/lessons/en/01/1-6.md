## Understand the problem

A tensor combines linear storage, a shape, an initial offset and strides. An axis stride tells how many storage elements to advance when that index increases by one. Multiple tensors can therefore share the same physical values while presenting them differently.

## How it works

A transpose can swap strides without copying data. This view can become non-contiguous: view cannot always flatten it. contiguous produces contiguous storage when needed; reshape returns a view when possible and may otherwise copy. A zero stride logically repeats a value, as in expand.

$$
\mathrm{position}(i)=\mathrm{offset}+\sum_k i_k\,\mathrm{stride}_k
$$

## Develop the reasoning

A contiguous (3,4) tensor typically has strides (4,1): advancing along a row moves one value, changing rows moves four. Its transpose has shape (4,3) and strides (1,4). The elements are unchanged but reading order differs. Contiguity is therefore a property of layout, not values. `expand` can create zero strides so multiple indices address the same element: arbitrary writing into that view can be ambiguous.

## Worked example

With offset = 5 and strides = (4,1), element [2,1] is at position 5 + 2×4 + 1 = 14. Modifying a view can modify the original tensor; clone creates an independent copy.

## Read the code

Run this example in a Python environment with PyTorch. In-browser execution is planned for V2.

```python
import torch

x = torch.arange(12).reshape(3, 4)
y = x.t()
print(x.stride(), y.stride())  # (4, 1), (1, 4)
print(y.is_contiguous())  # False
flat = y.reshape(-1)  # may allocate a copy
independent = y.clone()
```

## Understanding check

A contiguous (2,3) matrix contains [0,1,2] then [3,4,5]. What order results from flattening its transpose?

<details>
<summary>Reveal the worked answer</summary>

The transpose has rows [0,3], [1,4], [2,5], so the order is [0,3,1,4,2,5]. This generally requires reorganising storage for a contiguous 1D representation.

</details>
